## 4. ОПИСАНИЕ ПРОЕКТА

### Название
**MANI** — сервис онлайн-записи для бьюти-студии "Ноготочки"

### Назначение
Веб-приложение для автоматизации процесса записи клиентов к мастерам маникюра с возможностью управления расписанием, услугами и записями через административную панель.

### Целевая аудитория
- **Клиенты** — пользователи, желающие записаться на услуги маникюра
- **Администраторы** — сотрудники салона, управляющие записями, услугами и мастерами
- **Мастера** — специалисты, оказывающие услуги (просмотр своего расписания)

### Основные возможности

#### Для клиентов:
- Регистрация и авторизация (email/пароль или через Яндекс ID)
- Просмотр каталога услуг и мастеров
- Выбор даты и времени из доступных слотов
- Создание записи с выбором одной или нескольких услуг
- Просмотр своих записей в личном кабинете
- Отмена своих записей

#### Для администраторов:
- Просмотр всех записей всех клиентов
- Отмена записи от имени салона
- Завершение записи (отметка как выполненной)
- Управление услугами (добавление, удаление)
- Управление мастерами (добавление, привязка услуг)
- Настройка расписания мастеров
- Блокировка времени (обеды, выходные)

## 7. АРХИТЕКТУРНЫЕ РЕШЕНИЯ

### Структура базы данных

**Таблицы:**
- `users` — пользователи системы (клиенты, мастера, администраторы)
- `sessions` — активные сессии (хранятся SHA-256 хеши токенов)
- `masters` — мастера салона с привязкой к пользователям
- `services` — каталог доступных услуг
- `master_services` — связь мастеров и услуг (many-to-many)
- `schedules` — еженедельное расписание мастеров
- `time_blocks` — блокировки времени (обеды, выходные, отпуска)
- `appointments` — записи клиентов к мастерам
- `appointment_services` — услуги в конкретной записи
- `holds` — временные удержания слотов (TTL 5 минут)

### Защита от конфликтов

**Триггер базы данных `prevent_overlap`:**
```sql
CREATE TRIGGER prevent_overlap BEFORE INSERT ON appointments
BEGIN
  SELECT CASE
    WHEN EXISTS (
      SELECT 1 FROM appointments existing
      WHERE existing.master_id = NEW.master_id
        AND existing.status = 'booked'
        AND NEW.intentional_overlap = 0
        AND NOT (NEW.ends_at <= existing.starts_at 
                 OR NEW.starts_at >= existing.ends_at)
    )
    THEN RAISE(ABORT, 'OVERLAP')
  END;
END;
```

Триггер срабатывает **до вставки** в транзакции и блокирует сохранение записи при обнаружении пересечения времени у одного мастера.

### Расчёт доступных слотов

**Алгоритм** (`backend/src/availability.js:65-106`):

1. Получение базового расписания мастера (день недели, время начала/окончания)
2. Извлечение всех активных записей мастера на выбранную дату
3. Извлечение блокировок времени (обеды, выходные)
4. Расчёт суммарной длительности выбранных услуг
5. Генерация слотов с шагом 15 минут в пределах рабочего времени
6. Исключение занятых интервалов и блокировок
7. Возврат массива доступных слотов с UTC-временем

### Безопасность

**Многоуровневая защита:**

1. **Пароли:**
   - Хеширование через `scrypt` (Node.js crypto)
   - Индивидуальная соль для каждого пароля (16 байт)
   - Параметры: N=16384, r=8, p=1, keylen=32

2. **Токены сессий:**
   - Генерация: 32 случайных байта через `crypto.randomBytes()`
   - Хранение: SHA-256 хеш токена в БД
   - Передача: в HTTP-only cookie (не доступна JavaScript)

3. **OAuth:**
   - Authorization code flow с PKCE
   - Параметр `state` для защиты от CSRF
   - Хранится только постоянный идентификатор провайдера
   - Токены Яндекса не сохраняются в БД

4. **SQL-injection:**
   - Все запросы параметризованы через `db.prepare()`
   - Нет конкатенации пользовательского ввода в SQL

5. **Rate limiting:**
   - Ограничение неудачных попыток входа
   - Блокировка по IP/email после N неудачных попыток

2. В обоих войти под разными клиентами
3. Выбрать одного мастера, одну дату, один слот
4. Одновременно (в течение 1-2 секунд) подтвердить запись

**Ожидаемый результат:**
- Первый клиент создаёт запись успешно
- Второй клиент получает ошибку "Выбранное время занято"

**Фактический результат:** ✅ Триггер БД блокирует вторую запись

## 13. ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ

1. **Нет email/SMS уведомлений**  
   Клиенты не получают уведомления о создании/отмене записи

2. **Нет истории изменений**  
   Не логируется, кто и когда изменял запись

3. **Простой календарь**  
   Используется HTML `<select>` вместо визуального календаря

4. **Нет статистики**  
   Администратор не видит графики загруженности мастеров

5. **Ограниченная мобильная адаптация**  
   UI оптимизирован для desktop, на мобильных требуется улучшение
