# Журнал разработки

## 2026-10-13 — база данных и API

- Выбран Node.js 24 и встроенный `node:sqlite`; внешние пакеты для SQLite и паролей не нужны. Причина — уменьшить зависимость от нативных модулей при переносе между Windows и Linux.
- Данные проекта отделены от исходников: миграции и скрипт тестовых данных входят в проект, файл базы хранится в игнорируемой папке `.data/`.
- Свободное время рассчитывается из графика, блокировок, записей и удержаний; отдельная таблица слотов не используется.
- Триггеры SQLite проверяют временное пересечение при INSERT и UPDATE; создание и изменение записей используют `BEGIN IMMEDIATE`.
- Пароли пользователей хешируются встроенным `scrypt` с отдельной солью. Токены с ограниченным сроком действия хранятся в базе как SHA-256-хеши.
- Создан отдельный черновой интерфейс в `draft-ui/`; файлы дизайн-прототипа в корне не менялись.
- Первичная проверка: миграция создала 14 таблиц; повторный запуск тестовых данных не увеличил количества пользователей (4), мастеров (2) и услуг (5). API чтения каталога и расчёта слотов ответил HTTP 200. API входа вернул 200; попытка клиента открыть административный список вернула 403; тестовая запись создалась, после чего слот исчез из выдачи.

## Ограничения и следующие проверки

- В папке проекта на момент разработки не было Git-репозитория; коммит и отправка на GitHub не выполнялись.
- Node.js на локальной машине был запущен из ZIP-дистрибутива; для `npm` в командной среде требуется PATH к распакованной папке.
- Доступность Node.js 24 и постоянного диска SQLite на конкретном тарифе BeGet нужно проверить перед деплоем.
- Нужно пройти в браузере сценарии регистрации, входа, конфликта слотов, удержания, отмены и проверки прав; ручная проверка внешнего вида браузера в этой сессии не выполнялась.
