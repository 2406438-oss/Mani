# Схема базы данных MANI

Схема покрывает прототип онлайн-записи и учебные сценарии: аккаунты и несколько ролей, каталог услуг, мастеров, их график и блокировки, удержание времени, запись, авторизацию токенами и административные настройки.

## Общие решения

- SQLite; идентификаторы — целые числа.
- Даты и время в БД хранятся как UTC ISO 8601 с миллисекундами (`YYYY-MM-DDTHH:mm:ss.sssZ`). Дата при выборе слота задаётся в часовом поясе салона из `product_settings`.
- Деньги хранятся в целых копейках.
- Пароли хранятся как строка `scrypt$N$r$p$salt$hash`; токены доступа — только как SHA-256-хеш.
- Свободные слоты вычисляются по графику, услугам, активным записям, блокировкам и действующим удержаниям. Таблицы готовых слотов нет.
- Активными и блокирующими время считаются записи со статусом `booked`. Отменённые, завершённые и `no_show` не блокируют время.
- Роли хранятся отдельными строками в `user_roles`, поэтому пользователь может иметь более одной роли.

## Таблицы

### `users`

| Поле | Тип | Обязательное | Назначение |
|---|---|---:|---|
| `id` | INTEGER | да | Первичный ключ |
| `email` | TEXT | да | Email для входа, уникальный, нормализованный в нижний регистр |
| `password_hash` | TEXT | да | Хеш scrypt с солью и параметрами; открытый пароль не хранится |
| `full_name` | TEXT | да | Имя пользователя |
| `phone` | TEXT | нет | Контактный телефон |
| `created_at` | TEXT | да | UTC-время создания |

### `user_roles`

| Поле | Тип | Обязательное | Назначение |
|---|---|---:|---|
| `user_id` | INTEGER | да | Внешний ключ на `users.id` |
| `role` | TEXT | да | `client`, `master` или `admin` |

Первичный ключ составной (`user_id`, `role`).

### `masters`

| Поле | Тип | Обязательное | Назначение |
|---|---|---:|---|
| `id` | INTEGER | да | Первичный ключ |
| `user_id` | INTEGER | да | Внешний ключ на профиль пользователя, уникальный |
| `specialization` | TEXT | да | Описание специализации |
| `is_active` | INTEGER | да | Активность мастера (0/1) |

### `services`

| Поле | Тип | Обязательное | Назначение |
|---|---|---:|---|
| `id` | INTEGER | да | Первичный ключ |
| `title` | TEXT | да | Название услуги |
| `duration_min` | INTEGER | да | Длительность в минутах, положительное значение |
| `price_kopecks` | INTEGER | да | Цена в копейках |
| `is_active` | INTEGER | да | Доступность для клиентов (0/1) |

### `master_services`

Связь многие-ко-многим между `masters` и `services`; составной первичный ключ (`master_id`, `service_id`).

### `schedules`

Рабочий интервал мастера на день недели (`weekday`: 1 — понедельник, 7 — воскресенье), локальное время салона в формате `HH:MM`. Составной уникальный ключ: мастер, день недели, время начала.

### `time_blocks`

Разовые блокировки мастера (перерыв, отпуск, выходной) с UTC-полями `starts_at` и `ends_at`. `master_id` может быть NULL для блокировки всего салона.

### `appointments`

| Поле | Тип | Обязательное | Назначение |
|---|---|---:|---|
| `id` | INTEGER | да | Первичный ключ |
| `client_id` | INTEGER | да | Внешний ключ на `users.id` |
| `master_id` | INTEGER | да | Внешний ключ на `masters.id` |
| `starts_at` | TEXT | да | Начало визита в UTC |
| `ends_at` | TEXT | да | Конец визита в UTC; больше начала |
| `status` | TEXT | да | `booked`, `completed`, `cancelled_by_client`, `cancelled_by_salon`, `no_show` |
| `intentional_overlap` | INTEGER | да | Осознанное наложение, допустимое только для администратора через API |
| `created_at` | TEXT | да | UTC-время создания |
| `updated_at` | TEXT | да | UTC-время последнего изменения |

`appointment_services` связывает запись с услугами и фиксирует цену/длительность на момент бронирования.

### `slot_holds`

Временное удержание выбранного интервала: пользователь, мастер, UTC-начало/окончание, время истечения. Истёкшие удержания удаляются при работе с расписанием и создании записи.

### `access_tokens`

Хеш токена (уникальный), пользователь, срок действия и дата отзыва. Сам токен хранится только у клиента.

### `product_settings`

Настройки салона, которые должен менять администратор, включая `timezone` (`Europe/Moscow`) и `slot_step_min` (шаг выдачи времени).

### `login_attempts`

Учёт неудачных попыток входа по нормализованному адресу-клиенту/IP и времени попытки; старые строки периодически удаляются.

## Ограничения и индексы

- Внешние ключи включаются в коде подключения (`PRAGMA foreign_keys = ON`) на каждом соединении.
- Email и токен уникальны; длительность услуги положительна; цена неотрицательна; статусы и роли ограничены перечисленными значениями.
- Индексы предусмотрены для ролей, расписания, блокировок, записей по мастеру/времени и по клиенту, удержаний по сроку действия и токенов.
- Триггеры `appointments` на INSERT и UPDATE запрещают пересечение интервалов одного мастера для `booked`-записей. Формула: `new.starts_at < existing.ends_at AND new.ends_at > existing.starts_at`; соседние интервалы разрешены. Отменённые записи не блокируют время. Для административного наложения API выставляет флаг `intentional_overlap`; последующие записи всё равно проверяются против него.
- Изменения записи выполняются транзакцией `BEGIN IMMEDIATE`, чтобы сериализовать конкурирующие записи в SQLite.

## Вычисляемое значение

Доступное время не хранится. Для выбранной даты API строит интервалы в графике мастера, вычитает блокировки, записи со статусом `booked` и неистёкшие удержания, затем оставляет начала, для которых помещается сумма длительностей выбранных услуг.
