# Отчёт о публикации сервиса

Проект: MANI — сервис онлайн-записи

> Статус: черновик, не готов к сдаче. Ниже отражены только фактически выполненные проверки на 27.10.2026. Сценарии записи клиента, проверки времени и входа через Яндекс не завершены.

## 1. Адрес и адресная строка

Адрес сервиса: https://mani-test.ru

Браузер открывает опубликованный интерфейс MANI, а не страницу заглушки хостинга. HTTPS работает: сертификат выпущен автоматически через прокси Coolify. При открытии `http://mani-test.ru` сервер возвращает перенаправление `307` на `https://mani-test.ru/`. После перехода на HTTPS корень сервиса перенаправляет на `/draft/`, где отображается интерфейс MANI.

Панель публикации находится на отдельном адресе `https://coolify.mani-test.ru`; этот адрес не используется как адрес клиентского сервиса.

## 2. Три сценария на боевом адресе

### Сценарий 1. Запись клиента целиком

Не пройден. В опубликованной базе намеренно нет демонстрационных данных. На момент проверки публичные API `GET /api/services` и `GET /api/masters` возвращали `{"items":[]}`. Поэтому в форме записи нет услуг и мастеров, клиент не может выбрать слот и завершить запись.

Для завершения сценария необходимо создать через вкладку «Администрирование» как минимум одну услугу и одного мастера с расписанием, затем в окне инкогнито зарегистрировать тестового клиента с вымышленными именем, email и телефоном и пройти запись до экрана подтверждения. В этот раздел должны быть внесены фактические данные клиента, выбранные услуга, мастер, дата, время и точный текст подтверждения.

### Сценарий 2. Админка под обычным клиентом

Частично проверен технически. Анонимный запрос к `GET /api/admin/appointments` получил ответ `401` с текстом `Войдите в аккаунт.` — сервер не отдаёт административные данные без токена.

Полный сценарий не пройден: нужен вход под созданным обычным тестовым клиентом и ручной ввод адреса админки/API. В текущей реализации отдельного маршрута `/admin` нет: `GET /admin` возвращает `404` с текстом `Страница не найдена.` Административные действия реализованы через защищённые маршруты `/api/admin/*` и вкладку «Администрирование», которая показывается пользователю с ролью `admin`.

### Сценарий 3. Проверка времени

Не пройден. Нет созданной клиентской записи и отсутствуют мастера/услуги. После выполнения сценария 1 необходимо сравнить дату и время одной и той же записи в кабинете клиента и во вкладке администрирования, затем записать оба значения и вывод о совпадении либо расхождении.

## 3. Вход через «Яндекс»

Не выполнен. В коде проекта не найдено реализации Яндекс OAuth или любых упоминаний `yandex`/`oauth`; на опубликованной странице есть только регистрация и вход по email и паролю. Поэтому нельзя описать экран согласия Яндекса, роль пользователя в базе, поля `password` и `provider`, повторный вход или содержимое таблицы пользователей без выдумывания фактов.

Для сдачи по этому пункту требуется реализовать и настроить вход через Яндекс OAuth, указав секреты только в настройках окружения/панели, затем пройти проверку из задания на реальном аккаунте Яндекса. Идентификатор приложения, секрет приложения, токены и пароли в отчёт не включать.

## 4. Разбор одной поломки публикации

Что видел: после назначения `https://coolify.mani-test.ru` для панели Coolify выпуск сертификата Let’s Encrypt не проходил. В журнале прокси было сообщение о невозможности выпустить сертификат и о том, что ответ на ACME-проверку HTTP слишком большой (`reading HTTP response body: reader size limit exceeded`). При открытии основного адреса отображалась страница `503 Service Unavailable`.

Чем оказалось: DNS-запись поддомена уже указывала на VPS, порты 80 и 443 слушались прокси. Проблема была в состоянии конфигурации Traefik/Coolify: служебная страница обработки неизвестных запросов перехватывала HTTP-проверку вместо корректной обработки ACME challenge.

Как чинили: в Coolify открыли `Servers → localhost → Proxy`, сбросили стандартную конфигурацию Traefik и перезапустили прокси. После этого Let’s Encrypt выпустил сертификат, и `https://coolify.mani-test.ru` стал открывать страницу входа Coolify. Затем приложение MANI было развёрнуто на основном домене.

Как убедился, что починилось: внешний запрос к `https://coolify.mani-test.ru` вернул страницу входа Coolify, а `https://mani-test.ru/draft/` вернул `200 OK`. Повторное развёртывание приложения также завершилось успешно.

Чем эта поломка отличалась от локальных: ошибка была связана с маршрутизацией, сертификатом и обратным прокси на VPS; локально на компьютере нет доменного DNS, публичного HTTPS и Traefik, поэтому такой сбой там не воспроизводится.

## 5. Решение по персональным данным

Режим данных должен быть уточнён перед сдачей. Публичная версия не получила локальные демонстрационные аккаунты и записи из `db:seed`; это снижает риск публикации известных учебных паролей. Однако начальный администратор был создан через переменные окружения, и в отчёте нельзя заявлять, что используются только вымышленные данные, пока не подтверждено, какой email был указан.

Для безопасного учебного режима:

- использовать только вымышленные данные клиентов, мастеров, услуг и расписания;
- не просить и не вносить чужие реальные телефоны, email или записи;
- хранить SQLite в постоянном Docker-томе `/data` на VPS;
- не помещать секреты и пароли в GitHub или отчёт;
- при завершении работы удалить приложение и постоянный том в Coolify, затем удалить VPS и домен либо отключить их продление. После удаления VPS данные тома и SQLite-базы перестанут быть доступны; после удаления домена его адрес перестанет вести на сервис.

## Что осталось до сдачи

1. Создать вымышленные услугу, мастера и расписание в опубликованной админке.
2. В инкогнито зарегистрировать вымышленного клиента и пройти запись до подтверждения.
3. Проверить запрет доступа обычного клиента к админ-действиям и зафиксировать точный наблюдаемый текст.
4. Сверить одну запись в кабинете клиента и админке.
5. Реализовать и проверить Яндекс OAuth либо согласовать с преподавателем отсутствие этого требования для текущей версии проекта.
6. Уточнить режим персональных данных и заполнить раздел 5 в соответствии с фактическими данными.
