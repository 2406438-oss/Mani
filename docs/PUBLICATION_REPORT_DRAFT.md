# Отчёт о публикации сервиса

Проект: MANI — сервис онлайн-записи. Дата итоговой проверки: 30.10.2026.

## 1. Адрес

Клиентский сервис опубликован по адресу `https://mani-test.ru`. В адресной строке отображается HTTPS-адрес `mani-test.ru`, вместо страницы хостинга открывается интерфейс MANI. HTTP перенаправляется на HTTPS. Панель развёртывания находится отдельно: `https://coolify.mani-test.ru`.

## 2. Проверенные сценарии

### Запись клиента

В отдельном окне инкогнито создан учебный клиентский аккаунт с вымышленными данными. В клиентском интерфейсе выбраны услуга Маникюр с покрытием, мастер Галина Учебная и свободный интервал. Запись подтверждена на экране До встречи в студии: 3 ноября 2026 года, 10:30, мастер Галина Учебная, услуга Маникюр с покрытием. После записи сервер перестал выдавать интервал 10:30–11:30 по московскому времени как свободный.

### Обычный клиент и админка

Под обычным клиентом вручную открыт `https://mani-test.ru/admin`. Сервер отказал в доступе с сообщением Недостаточно прав для этого действия. Административный маршрут защищён серверной проверкой роли.

### Сверка времени

В клиентском подтверждении и в административной панели после обновления отображалась одна и та же запись: 3 ноября 2026 года, 10:30, Галина Учебная, Маникюр с покрытием, статус `booked`. Время совпало.

## 3. Вход через Яндекс ID

Реализован OAuth 2.0 authorization code flow с PKCE и `state`. В окне инкогнито Яндекс ID показал экран согласия приложения Mani-test только с правами на email и имя пользователя. После подтверждения пользователь вернулся на MANI, где открылся личный кабинет.

В базе для такого пользователя создаётся роль `client`. Локальный пароль пользователю не назначается: для совместимости со схемой таблицы хранится случайный `scrypt`-хеш, исходный пароль отсутствует и не известен пользователю. Связь с провайдером хранится в `external_identities`: провайдер `yandex` и постоянный идентификатор пользователя. Access token и refresh token Яндекса в базе не сохраняются.

Проверен повторный вход: после выхода и выбора того же Яндекс-аккаунта личный кабинет снова открылся успешно, новая учётная запись не создавалась. Client ID, Client Secret, токены и пароли в отчёт не включаются.

## 4. Healthcheck и сохранность

`GET /health` возвращает 200 и статус ok. В Coolify включена HTTP-проверка `GET http://localhost:3000/health`; последняя проверка контейнера завершилась со статусом `healthy`. SQLite находится в постоянном томе `/data`. После redeploy без переменных начального администратора каталог, мастера, график и созданная запись сохранились.

## 5. Поломка публикации

После назначения `https://coolify.mani-test.ru` выпуск сертификата Let’s Encrypt не проходил: в журнале прокси было сообщение `reading HTTP response body: reader size limit exceeded`, а адрес отдавал 503. DNS уже указывал на VPS, порты 80 и 443 были доступны; причиной оказалось состояние конфигурации Traefik/Coolify, перехватывавшее ACME-проверку. В Coolify открыли `Servers → localhost → Proxy`, сбросили стандартную конфигурацию Traefik и перезапустили прокси. После этого сертификат выпущен, адрес Coolify открыл страницу входа, а MANI успешно развёрнут. Внешняя HTTPS-проверка MANI возвращает 200 для `/health`. Локально такая ошибка не воспроизводится: она зависит от публичного DNS, ACME, HTTPS и Traefik на VPS.

## 6. Персональные данные и завершение

Режим публикации учебный. В каталоге и расписании используются вымышленные услуги и мастера; для приёмки создана учебная запись. Демо-скрипт с общеизвестными паролями в production не запускался. Пароли хешируются `scrypt`, токены сессии хранятся в SQLite только как SHA-256-хеши, токены Яндекса не сохраняются, секрет Яндекс ID находится только в переменных Coolify и не добавлен в Git, отчёт или чат. После завершения учебной работы планируется удалить приложение и постоянный том в Coolify, затем удалить VPS и отключить продление домена.
